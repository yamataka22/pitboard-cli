# pitboard の語彙

CLI が返す値の意味です。AI に読ませる短い版は SKILL.md（`pitboard skill show`）にあります。

## スペース

テナントの単位です。ユーザーは複数のスペースに所属できます。トークンはユーザー単位で、所属している全スペースにアクセスできます。
CLI は `pitboard space use ID` で保存した既定スペースを使います。決まり方は [configuration.md](configuration.md) を参照してください。

`pitboard space show` で、そのスペースの語彙（進捗カラム、プロジェクト、ラベル、メンバー）が分かります。AI はコマンドを組み立てる前にこれを見ます。

## 進捗カラムと state

進捗カラム（progress）はスペースごとにユーザーが定義します。名前はスペースによって違い、`done` カテゴリのカラムは**複数あることがあります**（例: 「リリース待ち」と「リリース完了」の両方が done）。

`state` は pitboard が導出する4値です。

| state | 条件 |
|---|---|
| `backlog` | 進捗カラムに置かれておらず、担当者もいない |
| `inbox` | 進捗カラムに置かれておらず、担当者はいる |
| `in_progress` | done カテゴリ以外の進捗カラムに置かれている。担当者の有無は問わない |
| `done` | done カテゴリの進捗カラムに置かれている |

「完了」の意味が人によって違う場合（エンジニアはリリース待ちで完了、マネージャーはリリース完了で完了）は、`--state done` ではなく `--progress ID` で特定のカラムを指定してください。

## progress_changed_at

今の進捗カラム（または「なし」）に置かれた日時です。

- 別のカラムへ動かすと上書きされます。同じカラム内の並び替えでは変わりません
- 誤って done に置いて戻したタスクは、戻した時刻になり `state` も done ではなくなります
- done カラム間の移動（リリース待ち → リリース完了）でも上書きされます
- 履歴が無い古いタスクは `null` です

「今週完了」は `--state done --progress-changed-since <週の始まり>` で取ります。「詰まっているタスク」は `--state in_progress` で取って `progress_changed_at` が古いものを見ます。

`--progress-changed-since` / `--until` を付けると、アーカイブ済みも含まれます。完了したタスクはアーカイブされることが多いためです。除きたければ `--archived false` を付けます。

## アーカイブ

`archived` は `state` とは独立した真偽値です。アーカイブしても `state` と `progress_changed_at` は残ります。既定の一覧はアーカイブ済みを除外します（`--archived true` / `all` で含める）。

アーカイブ済みのタスクを `task move` で動かすと、アーカイブは解除されます（Web と同じ挙動）。

## ポイント

サイズの見積もりです。pitboard のタスクは5日以内に終わる粒度が前提で、期限日はありません。

| point | 目安 | point_days |
|---|---|---|
| `h1` | 1時間 | 0.125 |
| `h4` | 半日 | 0.5 |
| `d1` .. `d5` | 1〜5日 | 1 .. 5 |

## kind

`confirmed`（タスク）と `issue`（未確定の課題）の2種類です。ボード画面はタスクだけを表示し、タスク一覧画面は両方を表示します。
`task list` は指定が無ければ両方を返します。ボード相当にしたければ `--kind confirmed` を付けます。`task create` の既定は `confirmed` です。

## 担当者・報告者・メンバー ID

`assignee`（担当者）は常に1人です。複数担当は付けられません。`owner`（報告者）はタスクを作った人で、API からは常にトークンの持ち主になります。
`assignee.id` や `owner.id`、`space show` の `members[].id` は同じ「メンバー ID」です。`me` はトークンの持ち主のメンバー ID に解決されます。

## updated_at

タスク自体の更新日時です。コメントや TODO の追加では動きません。「最近動きがあったタスク」を知りたい場合は `progress_changed_at` を見てください。

## コメントとメンション

コメントは1段の返信を持てます（返信への返信はできません）。`task show` の JSON では `comments[].replies[]`、表示では `[ID]` 付きで出るので、`comment add --reply-to ID` に使います。

メンションは markdown 中の `[@名前](mention:メンバーID)` という記法で、この形のときだけ相手に通知（メール / Slack / Chatwork。相手の設定による）が届きます。`@名前` と書くだけでは通知されません。`comment add --mention ID` を使うと、本文の先頭にこの記法を付けてくれます。自分自身へのメンションは通知されません。

削除済みのコメントは `task show` に出ません。コメントの編集と削除は CLI にはありません。
